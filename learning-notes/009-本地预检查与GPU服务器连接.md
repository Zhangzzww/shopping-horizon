### 4. 冻结哈希校验（含 CRLF 诊断）

数据与课程的冻结 SHA-256 记录在 `data/sft_curriculum/manifest.json` 的 `source/labels/evaluation` 字段，环境运行时文件记录在 `data/environment.json` 的 `runtime_files_sha256`。

```bash

grep -c $'\r' data/sft_pure_v4/all.jsonl

# 验证 CRLF→LF 后哈希是否等于冻结值
tr -d '\r' < data/sft_pure_v4/all.jsonl | sha256sum
```

## 三、发现的问题与修复

| 问题 | 根因 | 修复 |
|---|---|---|
| dry-run 哈希不匹配 | `core.autocrlf=true` + 无 `.gitattributes` | 新增 `.gitattributes`（`* text=auto eol=lf` + 二进制显式排除）；本地 `core.autocrlf=false`；214 个文本文件 CRLF→LF |
| 课程测试失败 | 测试用 `.endswith("stage-a/merged")`，Windows 下 `str(Path)` 是反斜杠 | 改为 `Path(...).as_posix().endswith(...)`，共 3 处 |
| `web_agent_text_env.py` 清单过期 | commit 改文件后未更新 `environment.json` | 未改（GRPO 前审查，不阻塞 SFT） |

CRLF→LF 的批量转换（跳过二进制）用 Python 完成，关键点：

```python
import subprocess
from pathlib import Path

BINARY_EXT = {".gz", ".parquet", ".png", ".jpg", ".jpeg", ".sqlite3", ".whl"}
for rel in subprocess.check_output(["git", "ls-files"], text=True).splitlines():
    p = Path(rel)
    if p.suffix.lower() in BINARY_EXT:
        continue
    raw = p.read_bytes()
    if b"\x00" in raw[:8000]:      # git 二进制启发式
        continue
    if b"\r\n" in raw:
        p.write_bytes(raw.replace(b"\r\n", b"\n"))
```

本地补丁需保留（服务器重新 clone 后要重新打）：`engine.py`、`smoke_shop_env.py` 各加 `encoding="utf-8"`（Windows 默认编码是 cp1252 而非 utf-8）。

**提交换行策略改动时的标准做法：**

```bash
git add --renormalize .
git add .gitattributes
git commit -m "chore: lock LF line endings via .gitattributes"
```

注意：`git status` 在换行迁移后会显示大量「modified」，这是 CRLF→LF 改变文件字节数导致的 stat 缓存过期；`git diff` 的实际内容对比只有 3 个文件。二进制文件（parquet/gz/png/jpg）需确认未被误改。

## 四、VS Code Remote-SSH 连接 GPU 服务器

训练必须在 Linux 上跑（veRL/vLLM 是 Linux+CUDA 专属），本地 Windows 只负责检查与编辑。连接方式：

### 4.1 本地 Windows 准备

- Windows 10/11 自带 OpenSSH 客户端（`ssh`、`ssh-keygen`），无需额外安装 Linux。
- VS Code 安装扩展 **Remote - SSH**（`ms-vscode-remote.remote-ssh`）。

### 4.2 生成 SSH 密钥（租卡前就能做）

**时间线先说清楚：** SSH 配置分两段——**租卡前只做「生成密钥」**（这步和服务器无关，随时能做）；**租卡后才填 IP / 端口 / 用户名并上传公钥**（因为平台要等你下单开机后才会分配这些信息）。

**① 生成密钥对**（PowerShell）：

```powershell
ssh-keygen -t ed25519 -C "你的邮箱"
# 一路回车即可，默认生成到：
#   私钥 C:\Users\你\.ssh\id_ed25519        —— 绝不能外传
#   公钥 C:\Users\你\.ssh\id_ed25519.pub    —— 之后要放到服务器
```

输出里的 `The key fingerprint is: SHA256:...` 只是公钥的指纹（哈希摘要），**不是私钥**，无需保存或上传。

**② 查看公钥内容**（PowerShell，或 `notepad $env:USERPROFILE\.ssh\id_ed25519.pub`）：

```powershell
Get-Content $env:USERPROFILE\.ssh\id_ed25519.pub
# 输出一行：ssh-ed25519 AAAA...很长的乱码... 你的邮箱
```

这一整行就是公钥，后续贴到服务器 `authorized_keys` 或平台控制台。

### 4.3 配置 SSH 别名与上传公钥（租卡后）

租卡下单并开机后，平台会给你 **IP、端口、用户名（常为 `root`）、密码**。这时才做下面两步。

**③ 编辑 SSH 别名**：编辑 `C:\Users\你\.ssh\config`（不存在则新建）：

```text
Host gpu-server
    HostName <平台给的IP或域名>
    User <平台给的用户名，通常是 root>
    Port <平台给的端口>          # 关键：国内平台常是随机端口，不是 22
    IdentityFile ~/.ssh/id_ed25519
```

**④ 上传公钥**（任选其一）：

- **平台控制台粘贴**：AutoDL 等平台的控制台有「SSH 密钥 / 免密登录」入口，直接把 ② 里那行公钥贴进去，最省事。
- **本地推送**（PowerShell）：
  ```powershell
  type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh -p <端口> root@<IP> "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
  ```

**平台端口注意点：** 国内租卡平台（AutoDL、恒源云等）通常**不用 22 端口**，而是每个实例分配一个随机高位端口；登录指令一般形如 `ssh -p 12345 root@region-xxx.autodl.com`。控制台会直接给出一条「SSH 登录指令」，照抄即可。不要把 `Port` 想当然写成 22——填错就连不上。若平台支持免密登录，务必优先用它（或把公钥贴进控制台），避免每次输密码。

### 4.4 用 VS Code 连接

1. 左下角绿色「><」图标，或 `F1` 输入 **Remote-SSH: Connect to Host...**。
2. 选择 `gpu-server`（第一次输入密码或走密钥）。
3. 连接后 VS Code 会在服务器上装远程服务端组件，然后 `Open Folder` 打开仓库目录。

### 4.5 服务器上第一步（关键：换行与依赖）

`git config` 需要设置正确，否则服务器也会出现 CRLF/哈希问题：

```bash
# 若 .gitattributes 已提交并推送，clone 会自动得到 LF，无需额外设置；
# 若尚未推送 .gitattributes，先设置：
git config --global core.autocrlf input   # 或 false

git clone <仓库地址>
cd shopping-grpo-longhorizon
bash scripts/setup.sh          # 装 SFT/veRL/vLLM 依赖 + 解压商品 + 建索引 + 打补丁
```

**关键依赖顺序：** 本次新增的 `.gitattributes` 必须**先提交并推送**，服务器 clone 才会自动拿到 LF 内容，避免在服务器上重做一次换行修复。

### 4.6 多人协作：公钥、远程仓库与固定 checkout

**公钥：三人各一对，绝不共用。** 每人生成自己的 `id_ed25519`（私钥留各自电脑），公钥各自贴。服务器 `~/.ssh/authorized_keys` 每行一把公钥，三把都贴进去即可三人各自登录；共用同一把无法追责，且私钥外传等于失控。

**项目一致靠 git 远程仓库，不靠公钥、也不靠服务器文件互拷。** 代码唯一真相是团队自己的私有 GitHub 仓库（本项目来源是 `YYHDBL/shopping-grpo-longhorizon`，只作来源、不往那里推）。同步流程：

```text
各自本地开发 → git commit → git push
服务器跑训练 → git pull 拉最新代码
```

**服务器上每人固定一份 checkout。** 三人共用一台服务器时，各自 clone 到自己目录，训练时那份 checkout 固定不动（切到某个 commit 后不再 pull / 切分支），避免训练中途代码被换掉：

```text
/data/checkouts/<你的名字>/shopping-grpo-longhorizon   # 你的固定训练 checkout
```

模型、数据集、checkpoint 放共享目录（如 `/data/models`、`/data/datasets`、`/data/outputs`），三份 checkout 用软链接或统一路径指向同一份，不重复下载。

**协作约定：**

1. 同一时间只有一个人跑训练（GPU 就那么多，`nvidia-smi` 看谁占用，跑前确认卡空着）。
2. 训练进行中不要在那份 checkout 里 `git pull` / 切分支；新代码开新 checkout 或等训练结束再拉。
3. 本地补丁（如 `encoding="utf-8"`）必须提交进 git 并 push，不要各自漏打——一致性靠 git，不靠口头同步。
