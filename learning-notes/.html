002

Reward 与 Summary

终止、评分、汇总分别理解

奖励从哪里产生？
buy_now → click[Buy Now]
→ 环境 receive → SimServer.done
→ evaluate_purchase
→ RewardResult.to_dict
→ terminal_result / final_reward

环境依据商品、goal、所选规格和价格评分，无需LLM Judge。

奖励分支：顺序有意义
  1. 硬门槛不可验证：0，奖励无效。
  2. 否则硬门槛失败：−0.85。
  3. 偏好全满足、目标ID相同：1。
  4. 偏好全满足、ID不同：0.55。
  5. 其余：部分购买公式。

目标ID命中本身不保证满分。

匹配分与证据覆盖

品牌 .35、型号 .25、功能 .25、规格 .15。

只计算有要求的active维度，并重新归一化。

score = 通过数 / 要求数

coverage = 可验证数 / 要求数

coverage=1不代表全部通过。没有要求的维度不扣分。

终止与弃购
  • 环境repeat_loop：−0.65。
  • 环境max_steps：−0.50。
  • 合理弃购：−0.15。
  • 提前弃购：−0.35。

合理弃购需至少2个有效结果集、2个候选，且没有已知可接受候选。

候选可接受阈值不等于购买成功标准。

外层与环境 max_steps

外层rollout用尽预算，可能没有环境终局，reward_type为unknown。

环境tracker达到预算，才返回max_steps终局与−0.50奖励。

任务299第一次是外层8步停止，不能直接填上环境惩罚。

Summary 入口与聚合

summarize_trajectories(expected_task_ids, trajectories)

  • 只保留预期任务，预期ID应唯一。
  • 同任务后记录覆盖先前记录。
  • 读取reward_detail，不重算约束。
  • 返回字典，由调用方保存。

completed表示有记录，不等于环境结束。

统计分母与成功口径

成功率、done率、奖励有效率：除以预期任务数。

平均奖励、匹配分、步数：除以实际有记录任务数。

10题仅记录8题且reward都为1：均值仍为1，严格成功率最多0.8。

严格成功要求完整有效的gold_purchase。

未开启token计数时的0，不代表API无消耗。

TASK 299 / 数值闭环

把三个数值放回运行过程

搜索 → 查看候选 → 核验描述与功能 → 选择汤锅 → 购买。

偏好匹配分0.875不是成功概率
最终奖励0.18125部分购买分支
环境已结束是done=true
严格成功否非gold_purchase
① 激活维度重新归一化 
核心功能：8/10 = 0.8，权重0.25
汤锅规格：1，权重0.15
品牌与型号没有要求，不参与

(0.25 × 0.8 + 0.15 × 1) / 0.40
= 0.875
② 部分购买奖励映射 
min(上限, 基础偏移 + 缩放 × 匹配分)

min(0.25, −0.30 + 0.55 × 0.875)
= min(0.25, 0.18125)
= 0.18125
字段本次值含义
donetrue环境进入终局
reward_validtrue评分有效
purchase_successfalse未达到成功购买条件
strict successfalse未满足严格成功口径
